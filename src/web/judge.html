Comparison 1 - Food recommendation User: Kenzy (19 memories stored on Walrus)
Kenzy asked: "I want to make something Nigerian tonight, something creamy?"
Without Walrus Memory

Sure! For a creamy Nigerian dish I would suggest Nigerian Egusi Soup with a rich coconut cream and a fresh cream garnish. You could also try Afang Soup with a yogurt and cheese topping. Both are wonderfully rich. Would you like a full recipe?

With Walrus Memory (Active)

Since you are lactose intolerant I am leaving out all dairy. For creamy without dairy I would suggest Afang Soup thickened with blended waterleaf - it gets naturally silky without any cream. Ofe Onugbu with achi as a thickener also works beautifully. Leaving out bell peppers too since I know those do not work for you. Want the full recipe for either?

Memory did real work The stateless model suggested cheese and cream to a lactose-intolerant user. Walrus memory changed the ingredient list and avoided two allergens.
Comparison 2 - Travel advice User: Kosisochukwu (12 memories stored on Walrus)
Kosi asked: "I am booking a flight tomorrow, any tips?"
Without Walrus Memory

Here are some general tips: arrive 2 hours early for domestic flights, 3 hours for international. Consider booking an aisle seat for easier movement. Pack essentials in your carry-on. Download your boarding pass ahead of time. Happy travels!

With Walrus Memory (Active)

A few tips, and since you always prefer window seats I would flag: check in online early to lock in a window seat before others grab them - they go fast on busy routes. Since you are working on a decentralized app, download any dev resources you need before the flight since airport Wi-Fi is unreliable for builds. Safe flight!

Memory did real work Cheta recalled two stored facts (window seat preference, developer context) and tailored the response. The stateless model gave generic advice and suggested the wrong seat type.

Bug Bounty Reports (filed against MystenLabs/MemWal)

  • Python SDK lacks forget() method
    The HTTP API exposes forget/retire but the Python SDK has no equivalent method, forcing raw HTTP calls. Documented in docs/bug-reports/01.
  • scoring_weights parameter unreachable in search client
    The MemWal search endpoint accepts scoring_weights but the Python client provides no way to pass it. Always uses server defaults. Documented in docs/bug-reports/02.
  • Recall responses omit timestamps and blob IDs
    Memory recall returns text only. Timestamp, blob ID, and origin surface are absent, preventing provenance UI without a second fetch. Documented in docs/bug-reports/03.
  • Default server URL port mismatch between SDK and Docker runner
    SDK defaults to port 3000; Docker Compose defaults to 8080. First-run connection always fails without an explicit override. Documented in docs/bug-reports/05.
