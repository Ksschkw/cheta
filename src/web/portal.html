Four surfaces. One memory space per person. Zero data lock-in.

Cheta is a memory-first assistant on four surfaces that share one memory space per person. It mines each turn for durable facts, adjudicates every new fact against the notes it already holds, and keeps the store clean: duplicates are skipped before the write, superseded values are retired, and contradictions are surfaced.

Memory that decides

  • Durable facts Every turn is mined for the things worth keeping: an identity, a constraint, a preference, work, health or plans. Trivia and statements about the assistant itself are dropped.
  • Consolidation Each candidate fact is compared against its nearest stored notes and adjudicated as new, duplicate, update or contradiction before anything is written.
  • Duplicates collapse A fact that says the same thing is skipped rather than stored a second time, so the same value never competes with itself in later recall.
  • Superseded retired When you change your mind, the new value marks the old note superseded. It stops surfacing while the replacement takes its place.
  • Contradictions When two stored notes conflict and you did not say which wins, the turn tells you about the conflict instead of silently storing both.
  • Visible recall Under every reply, the web widget and the extension print the exact notes that were recalled for that turn. Nothing vague, nothing hidden.
  • Counterfactual Any recorded turn can be re-answered with memory switched off, so you can see the answer change rather than take the difference on faith.
  • Repair pass Asking to see your memory also runs a repair pass over the index that retires exact duplicates and self-contradictions already stored there.
  • Forget and correct /forget <number> retires one note and /correct <number> <text> replaces it with your own wording. Both are per-memory, not all-or-nothing.

Documents

Attachments are extracted locally, in-process, with no third-party service. The list below is generated from the parser's own advertised set, the same object it routes on, so it cannot overstate what is actually readable. Extracted text is capped at 12000 characters and files up to 20 MB are accepted.

  • PDF.pdf
  • Word.docx
  • PowerPoint.pptx
  • Excel.xlsx .xlsm
  • XML.xml
  • JSON.json
  • YAML.yaml .yml
  • HTML.html .htm .xhtml
  • CSV and TSV.csv .tsv
  • Plain text and source.txt .text .md .markdown .rst .log .ini .cfg .toml .py .js .ts .java .c .cpp .go .rs .sh .rb .php .cs .kt .swift .sql .css

Audio files are listed on the voice path below. Scanned images inside a PDF are images, and images cannot be read.

Refused by name, with the format to save as

  • .doc is the old binary Word format: save as .docx.
  • .ppt is the old binary PowerPoint format: save as .pptx.
  • .xls is the old binary Excel format: save as .xlsx.

There is no in-process converter for these, so they are refused with the replacement named rather than decoded into garbage.

Voice

Send a voice note or an audio file and it is transcribed first. The transcript is shown straight back to you before the answer, because a misheard word is the one failure you cannot see otherwise. Nothing is claimed unless the transcription actually succeeded.

  • Audio.mp3 .m4a .ogg .oga .opus .wav .webm .flac

Transcription needs a configured transcription provider. When none is configured the service says so and stores nothing, rather than guessing at the audio.

Tools the model is actually given

These thirteen definitions are the registry, listed here from the same registry the model is handed. A capability that is not registered is not offered, and the model is told exactly this list and nothing else, so it cannot claim a tool that does not exist.

  • memory_recallSearch the notes stored about you. Every hit carries the number that /forget uses.
  • memory_rememberStore one durable fact when you ask it to remember something.
  • memory_forgetRetire one stored note so it stops being recalled.
  • reminder_setSchedule a reminder that the application delivers later.
  • reminder_listList your pending reminders with their due times.
  • fetch_urlRead one public page as text. http and https only, non-public addresses refused, 6000 characters returned.
  • web_searchSearch the public web; up to 8 results as title, URL and snippet. A snippet is not the page, so a result is fetched before it is quoted.
  • crawlFollow links from a URL. robots.txt is honoured for the RantiBot user agent, and the bounds are in code: 8 pages, 256 KB per page, 12000 characters total, a delay between pages.
  • wikipediaArticle summary from the free MediaWiki REST API. No key.
  • weatherCurrent weather and a three-day forecast from Open-Meteo. No key.
  • document_questionAnswer from a document attached to the conversation. Registered on every surface; it has something to read where attachments arrive.
  • calendar_eventCreate one calendar event and send it as an .ics file. No account, API key, OAuth consent or network: you open the file and your own calendar adds it. The assistant cannot add anything to your calendar itself, and says so.
  • calculateExact arithmetic. The expression is parsed against a whitelist; eval is never used. No variables, functions, units or dates.

All thirteen run inside the same agent loop on every surface that reaches POST /chat/turn, which is all four. Deliberately absent: a tool that logs into a third-party account with a password typed into the chat. Accepting a credential in a message and replaying it against an arbitrary site is credential custody, and it is not built.

Reminders

  • Scheduled Ask in plain words and reminder_set stores the text and a resolved due time. Times can be relative like +30m or absolute like 2026-01-31T09:00:00Z.
  • Delivered later A background scheduler polls the reminder table every 30 seconds and pushes anything due over the surface that stored it, without being asked.
  • Exactly once Claiming a due reminder is a single atomic database transition, so two overlapping ticks cannot both send it. If the push fails, the reminder is released back to pending and retried, so nothing is lost either.

Delivery needs a surface with a message channel, and today that is Telegram. A reminder stored where there is no push channel is kept and retried rather than reported as delivered. On a surface that can also receive files, setting a reminder sends it as an .ics calendar entry built by the same generator as calendar_event; the reminder itself still fires at the exact due time.

Where the surfaces are not equal

  • Documents, voice notes and .ics calendar files arrive or leave as attachments, which is the Telegram surface. The widget, CLI and extension send and receive text.
  • Reminder push and the pairing notice need a push channel, so both are Telegram today.
  • Commands are dispatched by the service on POST /chat/turn, so /start /help /memories /forget /correct /link /unlink /pair /sessions /unpair work on all four. The extension also answers /start, /memories and /help locally.
  • The extension declares its own surface identity, which the backend accepts alongside telegram, cli and web.

Pairing

  1. On a client you already use, run /pair. Cheta mints a one-time code bound to your memory space.
  2. On the new client, enter /pair <code>. It joins the same space, and your notes are copied across.
  3. The originating client is told that a new client joined, with the surface and display name, and how to remove it.

Codes work once and expire. The notice back to the originating client requires that client to have a push channel, so today it is delivered on Telegram; an origin on another surface is not told. /sessions lists every client in the space and /unpair removes one.

What it cannot do

In the same words the first message uses: I cannot log into your accounts, I cannot read private pages you are not viewing, and I cannot understand images or video.

  • No erasure Walrus Memory has no delete and the relayer is append-only. /forget retires a note so it stops surfacing; the blob itself stays until its storage expires.
  • Weak matches Recall has no default relevance floor, so a weak match can still be returned. Salience re-ranking reorders the candidates; it does not invent a cutoff that is not configured.
  • No store listing The extension is not in any store. It is loaded unpacked or as a temporary add-on.
  • Offline fallback With no credentials the app runs against an offline mock memory client and a deterministic offline model. It is loud about being a fallback, and /health names the mode.
